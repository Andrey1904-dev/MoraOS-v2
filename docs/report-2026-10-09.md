## 4. Что требует секретов или настройки Supabase

1. **Миграция 0005** — применить к проекту (`/settings` без неё показывает подсказку, не падает).
2. **AI в боте** — секреты `AI_API_KEY` (+ `AI_BASE_URL`, `AI_MODEL`) у сервиса бота (Node-
   сервер или секреты Edge Function). Без ключа команды Ideas/Briefings честно сообщают
   о ненастроенном провайдере и ничего не выдумывают и не пишут в журнал.
3. **Дайджест** — cron на машине с `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`,
   `TELEGRAM_BOT_TOKEN`: `scripts/telegram-notify.mjs` (см. `docs/setup.md`, раздел
   «Дайджест-уведомления»). Включение — только владельцем в `/settings`.
4. Остальное (токен бота, ключи Supabase, webhook-секрет, переменные сборки) — как раньше,
   см. `docs/setup.md`.

## 5. Что проверено

**Тестами (131: 49 unit + 36 mini-app + 46 telegram):** все команды и экраны на моках;
авторизация и порядок «auth → rate-limit»; модерация черновиков (approve/dismiss/устаревшие
кнопки/счётчики); настройки и переключатели; дайджест (opt-in, watermark, дублей нет);
AI-честность и AI-журнал; callback_data ≤ 64 байт; drift Edge-копий; белый список deep links
против маршрутов `App.tsx`; привязка/отвязка Telegram — исходные сценарии не тронуты и зелёные.

**Сквозная проверка (локальные моки, не production):** три прогона `scripts/telegram-notify.mjs`
против мок-сервера — доставка 1 сообщения, пропуск по мин. интервалу, отсутствие дублей
после watermark.

**Полный набор:** `npm run check` (lint, typecheck, тесты, smoke ×5, build, check:dist,
sync:edge --check) — зелёный; `npm audit --omit=dev` — 0 уязвимостей.

**Не проверено:** живой продакшн (Supabase, Telegram API, Edge Function в облаке) —
все интеграции проверены на моках и локальной сборке. E2e в Chromium в песочнице
не запускался (нет браузера); e2e остаётся шагом CI.

## 6. Оставшиеся проблемы и риски

1. **Интеграции не реализованы** — Fanvue/TikTok/Instagram/Threads: ни коннекторов, ни
   доставки сообщений фанам нет ни в вебе, ни в боте. Экраны говорят об этом прямо.
2. **AI-провайдер — только в боте.** Веб-UI по-прежнему работает на MockAIProvider
   (помечено); проксирование реального провайдера в веб — отдельная задача.
3. **Движка автоматизаций нет** (ручной запуск из консоли). Дайджест сообщает об ошибках
   запусков, которые есть в `automation_runs`.
4. **Тумблеры уведомлений в веб-Settings — локальный state**, не связаны с таблицей
   `telegram_notification_settings` (управление — из чата). При желании веб может читать
   таблицу: RLS-политика `select` для владельца уже есть.
5. **Дайджест требует внешнего cron** — в репозитории нет общего планировщика; шаг
   задокументирован, по умолчанию всё выключено, спама не будет.
6. Требуется действие владельца из предыдущего аудита (required checks, секреты,
   `--disable-signup`) — не закрывалось в рамках этой задачи.
