## 2. Что уже работает для Mara OS

- **Бот** (`bot/core.mjs` + идентичная копия в Edge Function `telegram-api`, синхронизация закреплена тестом и `sync:edge`): команды `/start /menu /help /link /unlink /fans /messages /content /analytics /tasks /ai`, inline-клавиатуры с редактированием экранов вместо спама, HTML-экранирование пользовательских строк.
- **Привязка аккаунта:** одноразовые коды (Crockford base32, 50 бит, SHA-256-хэши, TTL 10 мин), **двухэтапное подтверждение** (preview аккаунта → confirm), лимит попыток per-account через Postgres (`consume_rate_limit`, fail-closed), двухшаговая отвязка. Таблицы `telegram_links`/`telegram_link_codes` доступны только service-role.
- **Mini App:** SDK грузится только в среде Telegram; `initData` для авторизации **не используется** (вход — штатный Supabase Auth, как и требуется); deep links только из белого списка `START_ROUTES`; CSP в прод-сборке.
- **HTTP API** (`bot/api.mjs`): таблица маршрутов и методов (405 с `Allow`), CORS по allowlist, лимит тела, `safeEqual` для webhook-секрета, безопасные ответы об ошибках, `/health` без утечек.
- **Данные:** бот читает те же таблицы, что и веб-панель (`fans`, `subscriptions`, `conversations`, `content`, `revenue_events`, `tasks`, `ai_runs`), строго по `user_id` из `telegram_links`. Параллельной CRM нет.

## 4. Что работает как демонстрация / честные ограничения

- **AI pipeline:** в вебе работает `MockAIProvider` (результаты помечены mock). `HttpAIProvider` (OpenAI-совместимый, env `AI_API_KEY/AI_BASE_URL/AI_MODEL`) существует для серверной стороны, но **не подключён к боту** — у бота AI-функций нет вообще.
- **Автоматизации:** движка исполнения нет; веб даёт ручной запуск/паузу. README и UI говорят об этом честно.
- **Коннекторы Fanvue/TikTok/Threads/Instagram:** не реализованы; «Approve» в инбоксе ставит `approved`, доставка фану не выполняется (и так написано в UI).
- **Уведомления:** механизма нет. В вебе тумблеры в Settings — локальный state, в Telegram ничего не уходит; Topbar показывает демо-уведомления.

## 6. Решения по архитектуре изменений

1. Бот остаётся read-mostly. Одобрение черновика в чате повторяет семантику веб-репозитория (`status=approved`, без `sent_at`, декремент `awaiting_approval_count`) — доставки фану не происходит, рискованных действий из бота нет.
2. AI в боте — только через реальный OpenAI-совместимый endpoint (`AI_API_KEY` на сервере, никогда не `VITE_*`). Без ключа команды честно отвечают «провайдер не настроен», никаких выдуманных результатов. Каждый запуск пишется в `ai_runs` (журнал).
3. Уведомления opt-in: таблица `telegram_notification_settings` (RLS: владелец читает; пишет бот через service-role), дайджест отправляется внешним cron-скриптом только при наличии новизны (watermark) и с минимальным интервалом.
