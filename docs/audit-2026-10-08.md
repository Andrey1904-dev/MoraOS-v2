### F1 · Critical · CI на `main` красный, Mara OS не опубликована

- **Факт:** run `37804038020` (`main`, merge PR #17, 8 окт. 15:50 UTC) и run `37803688055` (PR #17) завершились с ошибкой на шаге «E2E Telegram Mini App». Шаги проверок и сборки прошли, deploy пропущен.

Тестовый сервер отдаёт 404 на всё вне `BASE_PATH`, поэтому приложение не загружается. Воспроизведено: кнопка «Explore demo mode» не появляется, таймаут 10 с.
- **Причина 2 — устаревший сценарий.** Даже с исправленным путём тест ожидает интерфейс LADA: маршруты `#/credit`, `#/expenses`, `#/garage`, `#/service`, пункты меню «Кредит», «Расходы», «Гараж» (строки 208–209, 249–255, 323–324 и далее). Воспроизведено: тест падает на `nav[aria-label="Primary navigation"]` → «Кредит».
- **Почему важно:** `.github/workflows/deploy.yml` задаёт `E2E_REQUIRED: '1'`, значит шаг обязательный. Любой merge в `main` будет красным и не выкатится. По GitHub API последний успешный деплой Pages — merge PR #16 (`4e3ab04`, 2 окт.), то есть LADA. PR #17 слит при красном PR-check, что указывает на отсутствие required status checks. Прочитать защиту ветки не удалось (HTTP 403).

### F2 · High · `telegram-bot.yml` (режим `full`) направляет webhook на несуществующий хост

- **Факт:** `scripts/telegram-bot-setup.mjs:56–59` определяет `projectRef` в порядке: `--project-ref` → `SUPABASE_URL` → `project_id` из `supabase/config.toml:6`, а там `project_id = "ladagrantacredit"`. В `.github/workflows/telegram-bot.yml` (шаг «Настроить бота», строки ~46–52) `SUPABASE_URL` не передаётся, поэтому используется `ladagrantacredit`.
- **Воспроизведено** (`fetch` подменён, к Telegram не обращались):
  - без `SUPABASE_URL`: `setWebhook url=https://ladagrantacredit.supabase.co/functions/v1/telegram-api`, а в выводе скрипта рекомендуется `VITE_TELEGRAM_API_URL = https://ladagrantacredit.supabase.co/...`;
  - с `SUPABASE_URL=https://dcgurmwvpgzmlfivxoso.supabase.co` адрес корректный.
  - DNS (проверено `getent`): `ladagrantacredit.supabase.co` не резолвится, `dcgurmwvpgzmlfivxoso.supabase.co` резолвится.
- **Для `deploy=true`** скрипт выполняет `supabase secrets set … --project-ref ladagrantacredit` и `supabase functions deploy telegram-api --project-ref ladagrantacredit` (строки 113–119). Это не настоящий ref: ref проекта — 20 символов, как `dcgurmwvpgzmlfivxoso`. Токен бота и webhook-секрет передаются аргументами командной строки (строки 114–115).
- **Почему тесты не поймали:** `scripts/smoke-telegram-setup.mjs` и `tests/telegram.test.mjs` не задают `SUPABASE_URL`, то есть путь по умолчанию не покрыт.
- **Рекомендация:** один источник project ref (переменная репозитория или явная константа), валидация формата (20 символов `[a-z0-9]`), падение при отсутствии. Привести `supabase/config.toml` к реальному ref. В workflow передавать `--api-url` явно. Добавить тест на путь без `SUPABASE_URL`.

### F4 · High · Rate limit привязки Telegram общий и срабатывает до аутентификации

- **Факт:** `supabase/functions/telegram-api/index.ts:232` — `consumeRateLimit` с ключом `ip:<значение заголовка Origin>` и лимитом 60. Ключ берётся из заголовка `Origin`, который выставляет любой клиент. Проверка идёт до `verifySiteSession` (строка 235). Все запросы с одним `Origin` делят один бакет на 10 минут.
- **Воспроизведено:** 60 анонимных запросов с `Origin` сайта → все 401. Затем легитимный запрос с валидным токеном → **429 «Слишком много попыток»**.
- **Дополнительно:** лимит хранится в памяти одного инстанса функции, поэтому он не общий даже внутри проекта. Node-транспорт (`bot/server.mjs`) ключует по `socket.remoteAddress`, там эффекта нет, но за прокси все клиенты получат один IP.
- **Рекомендация:** сначала аутентифицировать, потом лимитировать по пользователю. Для анонимного трафика использовать IP, который выставляет платформа (доверенный заголовок). Для надёжного лимита нужен общий store (таблица, Redis/Upstash и т.п.).

### F5 · Medium · Маршрут отвязки не проверяет HTTP-метод

- **Факт:** `index.ts:243` — `/api/telegram/link/delete` и `/api/telegram/link` выполняют отвязку при любом методе. Воспроизведено: `GET /api/telegram/link` с токеном → `DELETE telegram_links?user_id=eq.…`.
- **Оценка:** нужен Bearer-токен, поэтому CSRF нет. Но это нарушение REST и расхождение с Node-транспортом, где разрешён только `DELETE`.
- **Рекомендация:** проверять метод в маршрутизаторе для каждого пути и добавить тест.

### F6 · Medium · Коды привязки: 40 бит энтропии и риск социальной инженерии

- **Факт:** `bot/format.mjs:44` — `randomBytes(5)` → 10 hex-символов (`0–9`, `A–F`), то есть 2⁴⁰ вариантов. При этом `bot/core.mjs:33–35` и README описывают «10 символов A–Z0–9».
- **Смягчающее:** TTL 10 минут, одноразовость, лимит 8 попыток на пользователя. Но общий бакет уязвим (F4).
- **Риск:** злоумышленник создаёт код в своём чате и уговаривает владельца ввести его в консоли. После этого чат атакующего получает сводки по выручке, фанам и задачам (экраны `fans`, `analytics`, `tasks`).
- **Рекомендация:** не менее 8 байт или base32 (≥ 50 бит). В консоли показывать, какой чат привязывается (например, `@username`), и требовать явного подтверждения.

### F7 · Medium · Политика паролей, регистрация и seed

- **Пароль:** `src/pages/AuthPage.tsx:69` — минимум 6 символов. Для консоли с персональными данными фанов рекомендуется минимум 8 (NIST SP 800-63B) и проверка на утёкшие пароли, если доступна в тарифе Supabase.
- **Регистрация:** `docs/setup.md` рекомендует отключать подтверждение email (`--no-confirm`). При открытой регистрации любой человек может создать аккаунт на чужой адрес. Для консоли одного владельца стоит закрыть регистрацию после создания аккаунта владельца (`scripts/supabase-auth-setup.mjs` поддерживает `--disable-signup`).
- **Seed:** конец `supabase/seed/mara_seed.sql` привязывает демо-данные к «первому пользователю по `created_at`». При открытой регистрации это может оказаться не владелец. Лучше явный UUID.
- **Рекомендация:** пароль от 8 символов, закрыть регистрацию, в seed указывать UUID явно.

### F8 · Medium · Нет единой цепочки миграций БД

- **Факт:** `supabase/migrations/0001_mara_os.sql` (48 строк) только переименовывает `cars`, `loans`, `transactions`, `maintenance` в `legacy_*`. `CREATE TABLE` там нет. Схема Mara применяется вручную из `supabase/schema.sql` через Dashboard, отдельно выполняются `storage.sql` и seed.
- **Почему важно:** `supabase db push` на новом проекте не создаст схему. Порядок шагов держится только на документации.
- **Рекомендация:** превратить `schema.sql` в идемпотентную миграцию (`0002_…`), а storage и seed оформить как явные последовательные шаги.

### F11 · Medium · Сборка, производительность и данные

- **Нет code splitting по маршрутам.** `src/App.tsx` импортирует все 16 страниц статически, `React.lazy` не используется. Результат: один основной бандл 587 kB (173 kB gzip) и предупреждение Vite.
- **Демо-данные в продакшен-бандле.** `src/repositories/index.ts` статически импортирует `demo.ts`, а тот — фикстуры `src/data/*` (около 64 kB исходников, включая «Mara Quinn»). Они нужны демо-режиму, но их можно грузить лениво (динамический импорт при включённом демо).
- **Список фанов.** `src/repositories/supabase.ts:251–258` (`subscriptionsByFan`) передаёт все ID фанов в `in.(…)` одним GET. `fans.list()` (около строки 309) грузит всех фанов без лимита и фильтрует на клиенте. Замер supabase-js: URL растёт примерно на 39 символов на фана. При 200 фанах — около 7.9 KB, при 1000 — около 39 KB. Типичные прокси с лимитом 8 KB начнут отвечать ошибкой при нескольких сотнях фанов. Это оценка по расчёту, на живом Supabase не проверялось.
- **Облачный режим подменяет данные.** `src/repositories/supabase.ts:1277`: если в БД нет персонажа, отдаётся статичная карточка Mara из `ops-compat`. Вымышленные данные выглядят как сохранённые настройки.
- **`npm run preview` даёт пустую страницу.** `vite.config.ts:25` задаёт `base` только для `build`. Без флага `--base /MoraOS-v2/` ассеты `/MoraOS-v2/assets/*` отдаются с 404, страница пустая (воспроизведено в Chromium). Обход: `npx vite preview --base /MoraOS-v2/`.
- **Внешние ресурсы.** Google Fonts грузится как render-blocking из `index.html`, и это запрос к третьей стороне. Картинки персонажа и контента — хотлинк с Pexels в шести местах (`src/data/fans.ts`, `src/data/media.ts`, `src/pages/Content.tsx`), без `onError`-фолбэка. В рантайм-обходе (внешние запросы в песочнице блокировались) шрифты и картинки не загрузились, что показывает зависимость от сторонних хостов.
- **Предупреждение Vite:** `ops-compat` импортируется и статически (`src/repositories/index.ts`), и динамически (`src/repositories/supabase.ts:1277`), поэтому динамический импорт не выносит модуль в отдельный чанк.
- **Ошибка SVG в графиках.** `src/components/ui/charts.tsx:67`: если в ряду меньше двух точек, `smooth()` возвращает пустую строку, и путь области становится `" L640,150 L0,150 Z"` (без команды `M`). Браузер пишет в консоль `Expected moveto path command`. Воспроизведено в рантайм-обходе (две такие ошибки). Исправление: собирать `area` только когда `line` не пустой (например, тернарным оператором в той же строке, где задаётся `area`).

### F13 · Low–Medium · Безопасность: прочее

- **SMTP-пароль в аргументах CLI.** `scripts/supabase-auth-setup.mjs:176`, а в документации пример с `--smtp-pass re_xxx`. Пароль попадает в историю shell и в `ps`. Оставить только переменную окружения `SMTP_PASS`.
- **`npx --yes supabase` без пина версии.** `scripts/telegram-bot-setup.mjs:113–119` запускает CLI из npm с `SUPABASE_ACCESS_TOKEN` в окружении. Зафиксировать версию.
- **Сравнение webhook-секрета не константное по времени.** `index.ts`, `provided !== webhookSecret`. Риск низкий, но исправить легко (`timingSafeEqual`).
- **Сырой `error.message` в ответах 500.** `index.ts:281` и `bot/server.mjs`. Сейчас путь почти весь закрыт `ApiError`, но это латентная утечка внутренних деталей.
- **`/health` без авторизации** раскрывает URL вебхука, число необработанных апдейтов и текст последней ошибки Telegram.
- **CORS.** `http://localhost:5173` и `127.0.0.1:5173` разрешены в продакшене (`index.ts`, список `allowedOrigins`). Вынести в dev-конфиг.
- **Нет CSP.** GitHub Pages не даёт кастомных заголовков, поэтому стоит добавить `<meta http-equiv="Content-Security-Policy">` с ограничением источников. Telegram SDK грузится с `telegram.org` без SRI, это ожидаемо, но учитывать.
- **`storage_owner_folder` помечена `immutable`** (`supabase/storage.sql:22–24`), хотя зависит от `auth.uid()`, который `stable`. Исправить на `stable`.
- **Мок Auth слушает `0.0.0.0`** (`scripts/mock-supabase-auth.mjs:157`). Это тестовый инструмент, но лучше `127.0.0.1`.
- **`vite.config.ts`** содержит `allowedHosts: ['.e2b.app', …]` — конфиг песочницы в продакшен-репозитории.
- **Токен бота и webhook-секрет** передаются аргументами `supabase secrets set` (см. F2).

### F16 · Для решения владельца · Юридические и продуктовые риски

Это не юридическая экспертиза. Пункты требуют решения владельца и проверки специалистом.

- **Раскрытие ИИ.** AI-черновики отправляются фанам от имени персонажа «Mara» на платформе с 18+ контентом и PPV. Нужно проверить требования к раскрытию ИИ (например, ст. 50 EU AI Act) и правила Fanvue и Telegram.
- **Изображения реальных людей.** Фото персонажа и контента — стоковые снимки с Pexels (`src/data/media.ts`, `src/data/fans.ts`). Нужно проверить права на образ изображённых людей и условия лицензии. Текст README про «вымышленных персонажей» к фото реальных людей не относится.
- **Персональные данные фанов** (имена, handles, суммы покупок). В интерфейсе и репозиториях нет удаления фана и выгрузки его данных (поиск по `delete`, `remove`, `export` в `src/` не дал такого сценария; кнопка Export только показывает тост, см. F3). Если на фанов распространяются требования GDPR или аналогичных законов, это пробел. Нужна политика хранения и механизм ответа на запрос субъекта данных.

## 4. Положительные стороны

- Строгий TypeScript без `any` в `src/`; `noUnusedLocals` и `noUnusedParameters` включены.
- RLS включён на всех 23 таблицах. Таблицы привязки Telegram (`telegram_links`, `telegram_link_codes`) доступны только `service_role`.
- `link_telegram_account` и `mara_seed` отозваны у `PUBLIC`, `anon`, `authenticated`. SECURITY DEFINER-функции имеют `search_path`.
- Storage: бакеты приватные, доступ по папке `auth.uid()`, выдача через подписанные URL.
- Коды привязки хранятся хэшами (SHA-256), одноразовые, с TTL. Чат нельзя привязать к двум аккаунтам.
- Сервисный ключ используется только на сервере. В `check:dist` есть проверки на утечку токенов и service-role.
- В боте пользовательские строки (имя, названия задач, категории, агенты) экранируются через `escapeHtml`. В клиенте нет `innerHTML`, `eval`, `dangerouslySetInnerHTML`.
- Mini App принимает `startapp` и `?screen=` только из белого списка.
- Принцип human-in-the-loop выдержан в дизайне: агенты предлагают, человек одобряет (но см. F3 по реализации).
- Тесты синхронизации копий Edge Function и бота, smoke-проверки настройки бота без реального токена.
- Дизайн консоли аккуратный: плотная панель, графики рендерятся, на 375 px нет переполнения.
