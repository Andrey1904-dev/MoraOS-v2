# Чек-лист соответствия: решения владельца

Этот документ перечисляет вопросы, которые **не решаются кодом** и требуют решения владельца
проекта (и, где нужно, юриста). Технические меры, которые уже есть, отмечены. Сам проект
ничего из перечисленного не утверждает.

## Технические меры (уже реализованы)

| Мера | Где |
|---|---|
| Экспорт данных фана (JSON-досье: профиль, воспоминания, события, покупки, переписки) | `FanProfile` → «Export data»; `fans.exportData` |
| Удаление данных фана (каскад: переписки, сообщения, воспоминания, покупки, подписки; события фана) | `FanProfile` → «Delete data»; `fans.erase`. Записи выручки сохраняются без привязки к фану |
| Экспорт списка фанов в CSV с защитой от CSV-инъекций | `Fans` → «Export CSV» |
| Одобрение человеком: AI не отправляет ответы; ответ записывается со статусом `approved` | `Conversations`; доставка не подключена |
| Пометка AI-происхождения сохраняется у одобренных сообщений (`ai_generated`) | `supabase.ts`, `approveDraft` |
| Привязка Telegram только по одноразовому коду; предпросмотр аккаунта перед подтверждением | `TelegramSection`; миграция 0004 |
| Приватные Storage-бакеты; доступ к своей папке | миграция 0003 |
| Регистрация закрывается после создания владельца (`--disable-signup`) | `scripts/supabase-auth-setup.mjs` |
| Минимальная длина пароля 8 символов | `src/lib/passwordPolicy.ts`; `password_min_length` в Auth |
| В сборке нет секретов; токен бота и service-role ключ только на сервере | `npm run check:dist` |

## Решения владельца (не реализованы кодом)

### 1. Раскрытие использования ИИ

- Нужно ли сообщать фанам, что ответы или часть контента созданы ИИ, и как (текст, место, момент)?
- Если проект работает с пользователями в ЕС (включая Германию), проверьте требования прозрачности к
  ИИ-системам, которые взаимодействуют с людьми (ст. 50 Регламента (ЕС) 2024/1689), вместе с юристом.
- Нужна ли пометка AI-черновиков в интерфейсе фана (сейчас — только для оператора).

### 2. Права на изображения и образ персонажа

- Изображения Mara и её образ: кто владелец прав, есть ли договор, разрешено ли коммерческое использование?
- Изображения из Pexels (`images.pexels.com`): условия лицензии Pexels допускают ли использование в продукте и
  в коммерческих целях, нужна ли атрибуция?
- Изображения реальных людей: есть ли письменные согласия на использование их внешности и на ИИ-обработку?
- Ассеты с признаками сгенерированных людей: правила маркировки и хранения.

### 3. Персональные данные фанов

- Основание обработки (договор, законный интерес, согласие) и текст политики конфиденциальности.
- Срок хранения переписок, покупок и «воспоминаний» ИИ; автоматическое удаление по сроку — **не реализовано**.
- Передача данных подрядчикам (Supabase, Telegram, будущие провайдеры ИИ): договоры обработки (DPA) и
  регионы хранения.
- Порядок ответа на запросы субъектов данных (сроки; сейчас запрос выполняется вручную через экспорт/удаление).
- Учёт записей выручки: удаление фана не удаляет финансовые записи (они анонимизируются). Проверьте
  требования к хранению учётных данных.

### 4. Возраст и содержимое

- Проверка возраста фанов и владельца; правила для контента 18+ и платформ, на которых он размещается.
- Ограничения платформ (Telegram, Fanvue и др.) на контент и ИИ-переписку — сверьте с их правилами.

### 5. Платёжные и коммерческие условия

- Оферты, условия подписок и возвратов: в проекте офферы — образец, платежей нет.
- Налоговый статус выручки и требования к чекам.

## Что делать перед запуском с реальными фанами

1. Ответить на вопросы разделов 1–3 и зафиксировать решения (в этом файле или в отдельном документе).
2. Опубликовать политику конфиденциальности и текст раскрытия ИИ.
3. Проверить права на все изображения, которые попадают в интерфейс и в контент.
4. Включить автоматическое удаление по сроку хранения или записать ручной регламент.
